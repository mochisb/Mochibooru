# Mochibooru

**A little visual universe.** A self-hosted booru engine built with **Bun, TypeScript, Svelte 5 and SvelteKit**.

The web interface is English-only, with fixed `en-US` date formatting. It does not switch languages based on browser preferences or provide a language selector.

## Quick start with Docker

Requirements: **Bun 1.3.14** and **Docker with Compose v2**.

```bash
bun install --frozen-lockfile
bun run setup
docker compose up -d --build
```

Open **http://localhost:5173**. `setup` creates `.env` with a random secret and an absolute local storage path; it preserves any existing `.env`. Compose starts PostgreSQL and Redis, applies migrations and starts the web app and worker. Data is stored in persistent volumes.

Create your account at `/login?mode=register` and promote it to administrator:

```bash
docker compose exec web bun scripts/promote-admin.ts you@example.com
```

Refresh the page to see the moderation section. Accounts are never granted elevated privileges automatically on registration.

## Development with Bun

From the repository root:

```bash
bun install --frozen-lockfile
bun run setup
docker compose up -d db redis
bun run db:migrate
bun run dev
```

In another terminal:

```bash
bun run worker
```

The web app runs at **http://localhost:5173**. You can also use locally installed PostgreSQL and Redis: set `DATABASE_URL` and `REDIS_URL` in `.env`.

To promote an account from the host:

```bash
bun run admin:promote you@example.com
```

### Production build

```bash
bun run build
bun run start
```

The server generated by `adapter-node` runs **with Bun**, as does the worker. `PORT` and `ORIGIN` must match your installation; the generated `.env` uses port 5173. Start the worker in its own process.

## Configuration

| Variable             | Purpose                                                                |
| -------------------- | ---------------------------------------------------------------------- |
| `DATABASE_URL`       | PostgreSQL connection URL.                                             |
| `REDIS_URL`          | Redis connection for queues.                                           |
| `BETTER_AUTH_SECRET` | Session secret generated by `bun run setup`.                           |
| `ORIGIN`             | Exact public URL, including scheme and port.                           |
| `PORT`               | Port for the built web app; Compose uses 3000 internally.              |
| `SITE_NAME`          | Community name.                                                        |
| `REGISTRATION_OPEN`  | `true` or `false`; controls account registration.                      |
| `REQUIRE_APPROVAL`   | `true` to review new posts and member edits.                           |
| `MAX_UPLOAD_MB`      | Maximum image size; defaults to 20 MB.                                 |
| `STORAGE_DRIVER`     | `local` or `s3`.                                                       |
| `STORAGE_PATH`       | Absolute local storage path shared by the web app and worker.          |
| `S3_*`               | Optional endpoint, region, bucket and credentials; see `.env.example`. |

Restart the web app and worker after configuration changes. For S3, create the bucket and allow the service to read, write and delete objects. Media is served through the application so permissions also apply to original images.

`BODY_SIZE_LIMIT` is the built server's transport ceiling. The `.env` file and Docker image allow approximately 101 MB; the application also enforces `MAX_UPLOAD_MB`, including for requests without `Content-Length`.

## Search

```text
landscape sunset
cat -dog
pixel_art rating:safe
rating:any type:animated
width:>=1920 height:>=1080
sort:score
```

- Included tags are combined with AND; `-tag` excludes matches.
- Ratings: `safe`, `questionable`, `explicit`, `any`. Default: `safe`.
- Types: `image` for static images, `animated` for animated images.
- Dimensions: `=`, `>`, `>=`, `<`, `<=`.
- Sorting: `newest`, `oldest`, `score` (favorite count).
- Multiword tags use underscores: `pixel_art`.
- Syntax errors are shown to the user rather than silently ignoring filters.

Pagination is currently limited to 250 pages of 36 posts; refine the query to explore more results. Autocomplete counts are calculated from published `safe` posts.

## Commands

| Command                    | Description                                                  |
| -------------------------- | ------------------------------------------------------------ |
| `bun run dev`              | SvelteKit development server with live reload.               |
| `bun run worker`           | Media processing.                                            |
| `bun run check`            | Svelte and TypeScript checks across the workspace.           |
| `bun run test`             | Unit tests without external services.                        |
| `bun run test:integration` | Retries and idempotency with a migrated PostgreSQL database. |
| `bun run test:e2e`         | Browser workflow with the web app and worker running.        |
| `bun run db:generate`      | Generate migrations after schema changes.                    |
| `bun run db:migrate`       | Apply pending migrations.                                    |
| `bun run format`           | Apply Prettier formatting.                                   |
| `bun run format:check`     | Check formatting.                                            |

Before running the browser test:

```bash
bun x playwright install chromium
```

Use a **test installation** with `REGISTRATION_OPEN=true` and `REQUIRE_APPROVAL=false`. The test creates accounts and posts, and promotes its own account to check permissions. `DATABASE_URL` must point to the database used by the web app; `ORIGIN` or `E2E_BASE_URL` selects the browser URL. Integration tests clean up their records; the E2E test keeps its data for diagnostics.

Playwright loads the repository-root `.env` explicitly, including when invoked through `bun x`. Exported environment variables take precedence. A missing `DATABASE_URL` stops the runner before any browser tests start.

GitHub Actions uses disposable PostgreSQL and Redis services with test-only credentials declared in the workflow. `bun run setup` generates a fresh authentication secret for each job. CI does not require production credentials or repository secrets, so it can also run on fork pull requests. Keep deployment credentials in your installation's untracked `.env`.
